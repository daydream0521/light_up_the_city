# 点亮夜城 · Light Up the City

一款纯前端、程序化生成的浏览器 3D 光路解谜游戏。翻转屋顶镜面、安放库存器件、转动光塔，让光束穿过分光镜与闸门，点亮每一盏背灯，唤醒雨夜之城、爱琴余晖与两岸灯火。

## 在线体验

[打开现有 Qoder Sites 公网版本](https://light-up-the-city-oqwsk12x62f.qoder.zone)。三城版在 `feature/v3-integration`，供本地盲玩和预览验收。

## 本地运行

```bash
npm ci
npm run dev
```

打开终端显示的本地地址。生产构建：`npm run build`；预览构建：`npm run preview`；逻辑测试：`npm test`。

真实 Chrome 验收：`npm run test:e2e`（自动启动开发服务器，默认使用本机 Chrome，可通过 `CHROME_PATH` 指定浏览器）。测试覆盖两章新增关卡、阶段性复苏、收藏馆、直接点击 3D 器件、原九关完整流程（五关教学 + Reflection 移植四关，含库存放置/取回、背灯、闸门超额判定、通关条件面板、评分、刷新续玩、终局与重玩）及移动端触摸，截图写入 `test-results/`。工坊测试覆盖草稿恢复、独立浏览器中的分享挑战、二次创作和主线存档隔离。使用软件 WebGL 运行测试时，可通过 `E2E_RENDER_SCALE` 降低渲染分辨率，保留测试视口尺寸。移植关卡的来源、许可与规则对比见 [docs/PORTING.md](docs/PORTING.md)。

## 城市之旅与收藏

首页右下角的三张城市卡片可切换实时主题。25 关分属雨夜之城（01–09）、爱琴余晖（10–17）、两岸灯火（18–25）。三章首关随时可玩，后续关卡随本章进度开放。主按钮用于开始、继续或观赏已复苏的城市。「预览城市」可以提前观赏三座完整点亮的城市，已完成的章节可重玩。

「城市收藏」可预览完整城市，并按城市查看关卡进度与星级。三城的「查看复苏」按存档展示实际亮灯情况，城市预览和自由观赏则保留昼夜控制。章末可进入尚未完成的章节，三章全部完成后可重新开始。关卡来源和参考步数见 [v3 主线章节与关卡来源](docs/V3-JOURNEY.md)。

首次完成爱琴或上海的关卡后，会从刚点亮的区域切到全城，已恢复的灯火继续亮起。可以跳过演出，或直接进入下一关。两岸灯火的 24 秒灯光秀仍可在自由观赏中重播。

部署预览时上传完整的 `dist/`，含 `experiments/`、`assets/` 与 `journey/`。上海地理数据来源及公开前需确认的要求见 [上海重制说明](docs/shanghai-refined/README.md)。

## 操作与规则

三章主线统一使用 Reflection 规则引擎（`src/game/reflection.ts`），不再有旧版能量限制：

1. 点击「开始点亮」。关卡开始**不强制**阅读规则；右上角「说明」可随时查看本关完整玩法。
2. 点击场景中的器件旋转/翻转：镜面在 `/` 与 `\` 间翻转；背灯镜四向旋转（金色背灯一面被光击中即点亮）；分光镜既反射也让光直行；闸门切换南北/东西轴。带灰色锁标的器件不可调整。
3. 有库存的关卡：底部「库存器件」坞选中器件 → 点击发亮的屋顶放置；每次放置后自动取消选中；「取回」可收回放错的器件。
4. 通关需同时满足：背灯点亮数达标、库存全部放上屋顶、场上器件全部被光照到、闸门被光**恰好**穿过目标次数（超额同样失败）。顶部「通关条件」面板实时显示每项条件的满足状态。
5. 可拖动空白处转动视角、滚轮缩放；「重置」只重置当前关。
6. 独立过关按操作次数评 1–3 星（不超过标准步数得 3 星）。个人最佳优先保留更高的星级，同星时记录较少步数。点击顶部进度点可重玩已解锁关卡。
7. 每章完成后可查看城市全景，全部通关后可「再玩一次」。

主线 HUD 的「寻光指引」逐级提供思路、关键操作和完整演示。看思路保留原评分，使用关键引导最高得 2 星。完整演示由玩家确认通关，可解锁后续关卡并点亮城市，本次成绩无星级。重置或重玩后可以独立解谜。

声音默认关闭。右上角可开启声音，或在「声音设置」里分别调整音乐、环境音和操作音。三城以同一原创旋律编配雨声、海风海浪和江面环境，回到首页、开始解谜和进入演出时会调整声音层次。进度和声音偏好保存在当前浏览器。

## 造光工坊

1. 从首页进入「造光工坊」，在「我的关卡」中新建作品。在器件库（手机上位于底部）选器件并点屋顶摆放，点击场上的器件查看方向，或旋转、锁定、移动、删除。用「光塔」工具可把唯一的光塔移到空屋顶。「清空预置」保留光塔，可用「撤销」恢复。
2. 在「关卡与器件属性」里选择城市和区域，填写名称、玩家库存与背灯目标。新建作品继承入口城市。主题和区域随作品与链接保存，旧版作品默认使用雨夜之城。屋顶光路随预置器件实时更新。
3. 点「试玩」使用正式规则验证。初始布局已经满足通关条件时，编辑器会提示先调整布局。合法试玩通关后可分享，返回编辑时会恢复设计初态。修改布局、方向、锁定状态、库存或背灯目标后需重新通关。更换城市和区域可保留验证。
4. 用「保存」把草稿或已验证作品留在当前浏览器。「我的关卡」支持继续编辑、试玩、复制和删除。作品与主线存档独立。本地保存不等于跨设备云同步。
5. 点击「分享链接」发送包含初始谜题配置的链接。其他浏览器可以打开链接挑战，也可以「复制到我的关卡」导入一份可编辑草稿。分享链接需要指向能运行工坊的站点地址，从 localhost 生成的链接只能访问本机站点。

## Phase B.2 接入状态

工坊的本地验证会保留通关终态和有效操作。旧版已验证作品可沿用本地分享，首次云端发布前需要重新试玩以取得记录。服务端发布处理器可在本地测试，数据库绑定、部署、短链接和关卡广场由 [Qoder Sites 接手计划](docs/QODER-PHASE-B2-HANDOFF.md) 跟进。

## 技术

- Vite + TypeScript + Three.js，无后端、远程模型或贴图依赖。
- `src/game`：与渲染无关的关卡、Reflection 光路引擎、评分和存档规则。
- `src/scene`：程序化城市、3D 交互、镜头、雨与灯光。
- `src/ui`：语义化界面、通关条件面板与流程状态。
- `tests`：光路规则与 25 关可解性回归测试、真实浏览器 E2E。

协作与视觉约定见 [公共设计规范](docs/DESIGN.md) 和 [开发指南](docs/CONTRIBUTING.md)；移植来源与许可见 [docs/PORTING.md](docs/PORTING.md)，历史关卡设计记录见 [关卡设计说明](docs/LEVEL-DESIGN.md)。
