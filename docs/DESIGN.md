# 《点亮夜城》公共设计规范

## 体验原则

1. **城市是主角**：3D 场景占据整个视口，UI 只保留当前任务、镜面操作与必要控制；不添加营销区、数据卡片或说明长文。
2. **操作先于演出**：所有动画都可被状态机约束，不能阻塞镜面切换、重置、下一关与重玩。演出不能替代真实光路计算。
3. **光是叙事**：未点亮区域使用低亮冷色材质；完成区域以暖窗灯、街灯、屋顶标识依次亮起。通关后仍保留此前街区的亮灯状态。
4. **可读性优先**：主光束使用青色，分光后的分支依次使用薄荷绿、紫、琥珀加以区分；分光器为薄荷绿三棱柱，目标使用暖金色，镜面使用银白边框与青色底座；雨、雾和 Bloom 不能盖住这些信号。
5. **规则可预测**：主线统一 Reflection 规则——镜面折转 90°、分光镜反射+直行、背灯镜背面吸收点亮、闸门按轴计数且恰好一次。右上角「通关条件」面板实时显示每项真实胜利条件的满足状态；不引入无法口算的隐藏机制，也不再用旧版能量限制。

## 3D 场景约束

- 网格 +X 向东，+Z 向南，+Y 向上；逻辑光路高度固定为 `OPTICS_HEIGHT`。
- `/` 映射为 `东→北、北→东、西→南、南→西`；`\` 映射为 `东→南、南→东、西→北、北→西`。
- 光路终止靠 `x,z,dir` 访问集合截断循环（分光镜产生直行子光束），步数上限兜底；器件状态环颜色语义固定：未照到=灰、被照到=青、背灯点亮=金、闸门通过=紫、闸门超额=红。
- 每个分支的光束材质按分支序号缓存复用；脉冲、端点光斑随每次光路重算重建，旧几何与贴图必须 dispose。
- 关卡格子单位与世界坐标换算只能由 `gridToWorld` 处理；3D 装饰不得侵入判定路径。
- 器件点击使用与投影同高度的纯平面 raycast 拾取（所见格=所点格），悬停有光标反馈；库存器件有键盘可访问的等价按钮。拖动与点击通过位移阈值区分。
- 新建筑优先使用共享几何/材质与 InstancedMesh；窗户、雨滴、光束等重复元素禁止逐帧创建对象。
- 默认限制像素比，低性能设备减少雨滴、阴影与 Bloom，而不是降低光路可读性。

## 文案与状态

- 使用简短、具体的动词：「开始点亮」「重置」「继续」「再玩一次」。同一动作始终使用同一名称。
- 每关只保留名称、一句环境文案；状态面板显示操作次数与实时「通关条件」清单（背灯/库存/全命中/闸门，仅展示本关实际存在的条件）。关卡开始不强制弹规则简报；「说明」按钮可随时查询。教学关首次器件配一句短提示，玩家做出对应操作后自动消失。
- 过关文案固定为「操作 N 次 · 个人最佳 M 次」加 1–3 星；评分只按操作次数对照标准步数，不引入能量利用率等虚假维度。
- 关卡状态固定为 `intro → playing → levelComplete → playing … → finale`；完成动画期间锁定重复通关，不锁重置/静音。
- 移动端控件触控区域至少 44×44px；支持横竖屏，不依赖悬停。

## 提交前检查

1. `npm test`、`npm run build` 通过。
2. 新增关卡必须有解法回归测试（`tests/reflection.test.ts`）：初始布局不能直接通关；参考解在四条胜利条件下获胜；`parMoves` 不高于参考解操作数；难度应来自光网规划，而非单纯堆器件数量。
3. 教学关须让新机制先出现在简单可观察的环境（如旋转分光镜看到双束、改变闸门轴向看到计数变化）；保留移植关的关键布局与约束不得重新设计。器件/光源不得同格。
3. 镜面逻辑、3D 朝向、按钮符号三者一致；阻挡物与光路停止位置一致。
4. 实际浏览器至少走过受影响流程，检查控制台错误并保留关键截图。
5. 不将未验证的移动端、公网或性能能力写成已完成。
