# 《点亮夜城》公共设计规范

## 体验原则

1. **城市是主角**：3D 场景占据整个视口，UI 只保留当前任务、镜面操作与必要控制；不添加营销区、数据卡片或说明长文。
2. **操作先于演出**：所有动画都可被状态机约束，不能阻塞镜面切换、重置、下一关与重玩。演出不能替代真实光路计算。
3. **光是叙事**：未点亮区域使用低亮冷色材质；完成区域以暖窗灯、街灯、屋顶标识依次亮起。通关后仍保留此前街区的亮灯状态。
4. **可读性优先**：主光束使用青色，目标使用暖金色，镜面使用银白边框与青色底座；雨、雾和 Bloom 不能盖住这些信号。

## 视觉令牌

| 用途 | 色值 / 规则 |
| --- | --- |
| 夜色背景 | `#050916`，远景雾 `#0b1730` |
| 主文字 | `#edf4ff`；次文字 `#9aabc4` |
| 主光束 / 可交互反馈 | `#69e6f2` |
| 目标 / 已点亮窗灯 | `#ffcf82` |
| 控件表面 | 半透明 `rgba(7, 17, 34, .72)`，细边 `rgba(184, 216, 255, .16)` |
| 标题字体 | 本机宋体/衬线中文字体栈，细字重，较大留白 |
| 正文字体 | 本机中文黑体栈；正文至少 14px，主要操作至少 16px |
| 圆角 | 控件使用 `--site-radius`，不把所有容器卡片化；状态点保持圆形 |
| 动效 | 镜面 180–240ms；街区点亮约 1.2s；终局镜头约 3s；尊重 `prefers-reduced-motion` |

所有 Nudge 变量集中定义于 `src/styles.css` 的 `:root`。业务样式必须消费 `--site-*`，新增颜色应先判断能否归入现有语义令牌。

## 3D 场景约束

- 网格 +X 向东，+Z 向南，+Y 向上；逻辑光路高度固定为 `OPTICS_HEIGHT`。
- `/` 映射为 `东→北、北→东、西→南、南→西`；`\` 映射为 `东→南、南→东、西→北、北→西`。
- 关卡格子单位与世界坐标换算只能由 `gridToWorld` 处理；3D 装饰不得侵入判定路径。
- 可点击镜面必须有独立 raycast 命中体、悬停反馈、键盘可访问的等价按钮。拖动与点击通过位移阈值区分。
- 新建筑优先使用共享几何/材质与 InstancedMesh；窗户、雨滴、光束等重复元素禁止逐帧创建对象。
- 默认限制像素比，低性能设备减少雨滴、阴影与 Bloom，而不是降低光路可读性。

## 文案与状态

- 使用简短、具体的动词：「开始点亮」「重置」「继续」「再玩一次」。同一动作始终使用同一名称。
- 每关只保留名称、一句环境文案与当前目标；首关额外显示一次「点击镜面，让光转弯」。
- 关卡状态固定为 `intro → playing → levelComplete → playing … → finale`；完成动画期间锁定重复通关，不锁重置/静音。
- 移动端控件触控区域至少 44×44px；支持横竖屏，不依赖悬停。

## 提交前检查

1. `npm test`、`npm run build` 通过。
2. 新增关卡必须有解法回归测试，初始布局不能直接通关。
3. 镜面逻辑、3D 朝向、按钮符号三者一致；阻挡物与光路停止位置一致。
4. 实际浏览器至少走过受影响流程，检查控制台错误并保留关键截图。
5. 不将未验证的移动端、公网或性能能力写成已完成。
