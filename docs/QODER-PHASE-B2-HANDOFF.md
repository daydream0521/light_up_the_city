# Qoder Sites 接手计划 · Phase B.2

在 `feature/v3-integration` 的最新提交继续。使用独立 Qoder Sites 测试站点，并保留现有正式站点和 `main` 作为验收前的发布边界。P0 优先完成发布、发现与挑战，之后完成成绩对比和二次创作。

## 1. 确认测试站点能力

本次调查中，官方 CLI 1.1.98 的只读 `sites list` 返回 `sites_auth_required`。账户是否拥有数据库、Server Functions 和匿名访客权限，以及实际资源额度，需在已登录的 Qoder 会话确认。

- 在已登录的 Qoder CN 会话引用 `@sites`，或者在官方 CLI 中执行 `qodercn sites list` 与 `qodercn sites operations`。用站点 Skill 核对测试站点、数据库、Server Functions、匿名访问、限流、额度和费用。遇到账号授权或付费能力时记录所需操作，由项目负责人处理。
- 在独立测试站点建立最小的真实数据库读写链路。用退出登录或独立浏览器确认公网上的访客可以调用 Server Function。测试记录写入后刷新，再重新部署同一测试站点并读取该记录，确认数据库与静态部署的生命周期。生产配置文件已有发布记录，请勿将其当作测试站点绑定或数据库凭据。
- 官方 CLI 的数据库迁移和发布由会话内 Sites Skills 执行。使用该账号的 `operations` 和 `describe` 确认当期接口，记录测试站点采用的函数入口、绑定方式和迁移命令。参考 [Qoder Sites](https://docs.qoder.cn/qoder/sites) 和 [Qoder CLI Sites](https://docs.qoder.cn/cli/sites)。

## 2. 接入真实发布和读取

- 在测试站点创建只追加的公共关卡表，字段为 `id`、`puzzle`、`author`、`createdAt`、`creatorMoves`、可空的 `parentId`。由服务端或数据库生成 ID 和发布时间。测试一份作品再次发布会生成新记录，旧 ID 保持原内容。
- 将 Server Function 的发布入口接到 [postPublication](../src/server/publications.ts)，传入服务端数据库的插入函数。处理器接受 `{ puzzle, author, parentId, solution: { final, moves } }`，将操作重放到首次胜利并核对最终状态，只向插入函数交付公开字段。若平台以已解析的 JSON 传参，在入口限流和限制请求体大小后调用 [validatePublication](../src/game/publication.ts)。处理器当前上限为 128 KiB、2048 次有效操作。前端把平台使用的响应接到 201、422、413、503 的 UI 分支。
- 用同一后端提供按发布时间倒序的分页列表和按 ID 读取。两者只读取公开列，查无记录时返回 404。匿名访客经函数发布，数据库凭据和更新、下架权限留在站点服务端。为发布函数启用平台提供的匿名请求限流，记录实测策略。
- 原样保存通过校验的 `puzzle.city` 和 `puzzle.district`。城市编号 0、1、2 依次对应雨夜之城、爱琴余晖和两岸灯火，`district` 以所选城市的区域为准，范围 0–3。缺少 `city` 的旧记录按雨夜之城显示。本地发布处理器已通过主题字段的重放与公开响应测试。
- 寻光指引只写入主线完成记录和主线星级。发布仍以工坊 `Work.solution` 中当前作品的合法操作和终态为准。公开挑战沿用独立的挑战流程和成绩。
- 联调时复用 `Work.solution`。老作品中只有 `verified: true` 的记录需要重试玩。编辑器会清除影响玩法编辑后的旧证明。服务端对收到的当前 Puzzle 独立重放，旧操作只有在确实能解出所提交谜题且与最终状态一致时才可能通过。浏览器端长链接继续作为本地降级方式，其内容可编辑，也不携带服务端发布记录。

## 3. 接入发布、广场与短链接

- 工坊采集纯文本昵称，在有合格试玩记录时提供发布。等待服务端成功后再显示「已发布」并记录对应 ID。编辑本地副本不写回线上，玩法更新后重新试玩。成功发布弹出可复制的 `#p=<id>` 短链接。预置即通关保持草稿提示。
- 首页增加「关卡广场」。显示真实最新发布作品，涵盖加载、空库、请求失败和重试。每张卡片包含名称、作者、街区、参考步数、挑战和分享。用初始 Puzzle 绘制 5×5 CSS 或 2D Canvas 封面，显示光塔、器件类型和锁定状态。
- 从广场或短链接按 ID 读取记录，交给现有自定义挑战，提供重置、再玩、返回广场或首页。区分 404、网络失败和服务不可用。保留离线主线与本地工坊。公共列表从服务器读取，旧自包含链接走本地分享路径。

## 4. 成绩与 Remix

- 结算复用当前有效操作计数，显示本次步数、参考步数、按公开关卡 ID 保存的本地最佳及差值。将创作者步数标作参考。
- 从公开记录复制到本地独立草稿，保存 `parentId`。修改、重新验证并发布后，广场及挑战详情显示原作链接。公共记录缺失时显示来源已不可用。
- 游玩统计放到 P0 完成后处理。若保留，挑战开始时产生服务端会话标识，完成请求携带合法通关证明，数据库以会话唯一约束实现幂等。展示会话次数，低样本显示「难度待定」。如果平台限额或事务能力不足，先交付发布与挑战闭环。

## 5. 交付验收

1. 在测试站点以浏览器 A 新建、试玩并发布。浏览器 B 独立访问广场，进入挑战、通关并比较成绩，再用短链接独立打开同一 ID。
2. 查看刷新、重新部署后的同一条真实记录。复测本地修改与重新发布，旧 ID 内容和新 ID 独立。
3. 从浏览器 B 复制原关、修改玩法、重新通关、发布衍生作品，再跳转原作。
4. 直接调测试站点发布接口提交空证明、伪造 `verified`、初始即胜、锁定被改、非法或重叠摆放的请求，检查数据库没有新增记录。确认公开响应无解法。模拟网络或数据库故障并复查本地工坊和主线。
5. 运行项目构建、Vitest 及 Playwright。提交真实数据库读写和重新部署的验收结果，附测试站点地址、配置与命令、桌面和手机上的发布、广场与结算截图。将待开通权限和任何未实测事项列入交付。
