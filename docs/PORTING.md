# 关卡移植说明（Task A · feature/v2-puzzles）

本轮不再自主从零设计高难关卡，而是研究并移植成熟开源光路解谜游戏 **Reflection** 的代表性关卡与关键规则。

## 来源与许可

- 原作：**Reflection**（OrangoMango），<https://github.com/OrangoMango/Reflection>
- 许可证：**MIT**，完整文本见 `references/Reflection-LICENSE`。
- 关卡数据：`src/main/resources/misc/levels.data`；官方参考解：`src/main/resources/misc/solutions.data`。
- 玩法机制参考自原作源码：`core/Laser.java`、`core/World.java`、`core/Mirror.java`、`core/Splitter.java`、`core/SingleMirror.java`、`core/Checkpoint.java`、`ui/PlayScreen.java`。
- 第二优先级参考 HELIOS（muhmdusman/solistice-game）仅用于对照“可放置器件 + 分光”的思路，未复制其逻辑门系统。

按 MIT 要求，保留上述版权与许可声明；关卡布局与规则在原有 Three.js 引擎上重新实现，非逐字节拷贝。

## 原作规则（还原）

Reflection 在 5×5 网格上进行，胜利需**同时**满足四条（见 `PlayScreen.isLevelCompleted` 与 `updateWorld`）：

1. **全器件命中**：除空格、障碍、光塔外，场上一切器件（镜面、分光镜、单面镜、闸门，含玩家放置的）都必须被光经过（`hasLaser`）。
2. **背灯达标**：点亮的单面镜背灯数 ≥ 关卡目标数（`#N`）。单面镜只有一个“背灯”方向；光从背面射入被吸收并点亮，从其余方向射入则按单面镜规则反射或吸收但不亮。
3. **库存清空**：库存里的器件必须全部放到屋顶（`inventory.isEmpty`）。
4. **闸门恰好一次**：光穿过所有闸门（含库存里未放置的闸门也计入总数）的**允许方向**的总次数，必须**恰好等于**闸门总数；重复穿过会超额而失败。

器件语义：
- 镜面 Mirror：翻转 `/`↔`\`。
- 分光镜 Splitter：既按镜面反射，又让原方向光**直行**（生成子光束），与本作旧“分光器平分能量”不同。
- 单面镜 SingleMirror：四向旋转，只反射两个方向、吸收另外两个方向；背面被吸收即点亮背灯。
- 闸门 Checkpoint：可翻转到 N/S 或 E/W 轴，只允许该轴方向的光“通过计数”，光不被阻挡。
- 光塔 Laser：可旋转发射方向（部分关卡锁定）。

## 移植后的规则（改动）

- 复用并扩展了本作的光路引擎：新增 `src/game/reflection.ts`，方向约定沿用 `optics.ts`（0=E,1=S,2=W,3=N），原作方向 `r`(0=N,1=E,2=S,3=W) 映射为本作 `(r+3)%4`。四条胜利条件逐条实现，语义与原作一致。
- **主线统一规则（Task A.2）**：九关全部使用 Reflection 引擎，旧版能量机制从主线与玩家界面完全移除（`optics.ts` 仅保留光路结果类型）。教学关与移植关的操作方式、器件语义、胜利规则完全一致。
- **新增操作自由度**（通过 3D 场景 + 明确 UI 完成，非纯算法模拟）：
  - 有限库存器件：底部“库存器件”坞选择器件类型，点击屋顶空格放置；数量用尽自动取消选择。
  - 固定 vs 可调器件：`locked` 器件（对应原作 noRot/noFlip）显示灰色锁环且点击无效；可调器件点击循环旋转/翻转。
  - 放置区限制：`placementZones` 支持限制可放置格子（缺省为全部空格）；选中器件时高亮可放置格。
  - 闸门方向约束 + 库存闸门计数：完全按原作“恰好一次”的等式判定。
  - 取回：库存坞的“取回”工具可移除已放置器件并归还库存。
- 3D 渲染在 `CityScene.ts` 内新增器件外观（单面镜背灯球、闸门双柱拱、分光镜薄荷色面板、光塔喷嘴指向）与器件状态环（未照到=灰、被照到=青、背灯点亮=金、闸门通过=紫、闸门超额=红）。`cityGeometry.ts` 的城市美术、背景建筑、整体配色与后处理未改动，仅随关卡数据结构变化做了占用格计算的机械适配。

## 原作数据的版本不一致（重要）

`levels.data` 与 `solutions.data` 在上游并非同一版本，直接照抄会不可解。本轮据实处理：

- **LEVEL 20**：`levels.data` 在 `(1,0)` 有一块障碍，但官方 `solutions.data`（SOLUTION 14）的解基于**没有该障碍**的棋盘。移植时移除该障碍，使官方解在本作引擎下成立（vitest 已验证）。
- **LEVEL 50 / 75 / 92**：官方解与 `levels.data` 的锁定器件/障碍版本互相矛盾，在本作引擎下无法达成“全命中 + 背灯达标”，故**未纳入主线**；改选与官方解自洽的 **LEVEL 99** 作为压轴挑战。
- 九关的参考解（教学关推导解 + 移植关官方解）均可通过引擎校验（见 `tests/reflection.test.ts`）。

## 验收口径（区分两类）

- **功能正确性（已自动验证）**：`tests/reflection.test.ts` 用官方解/教学解驱动，断言九关在“全命中、背灯达标、库存清空、闸门恰好一次”下 `won=true`；并断言九关初始态不胜、库存未清空不胜、存在未命中器件不胜、单面镜背灯方向语义、背灯达标但闸门未过不胜、闸门超额不胜、`parMoves` 不高于参考解。真实 Chrome E2E 走完九关与移动端前三关。**vitest 与 Playwright 全部通过。**
- **游戏性（尚待真人盲玩）**：求解器通过、官方解成立、操作数较多，都**不能**直接证明关卡有趣或够难，也不能证明新玩家理解规则。最终难度、乐趣与教学效果由用户亲自盲玩评价；界面**不展示标准解法**（仅暴露 `window.__qoderTest` 投影/摘要钩子用于自动化，不含解法）。

## 当前玩法限制

- 单面镜/闸门的“旋转/翻转”为点击循环，未提供反向旋转；达到目标态的点击数即计入操作数（与原作 rotate90 单向一致）。
- 未引入计时、惩罚、逻辑门或其他无关机制；未开发关卡编辑器/每日挑战；未合并美术分支；本轮（A.2）不更新 Qoder Sites 公网版本。
