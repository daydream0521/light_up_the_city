# 开发指南

## 分支与提交

- `main` 保持可构建、可玩；多人功能开发使用 `feat/<简短主题>`，修复使用 `fix/<简短主题>`。
- 提交前同步主干，提交信息使用 `feat:`、`fix:`、`test:`、`docs:`、`style:` 或 `refactor:` 前缀。
- 一个提交只包含一个可说明的阶段；不要提交 `node_modules`、`dist`、本机配置、账号信息或临时浏览器数据。

## 模块边界

- `game/levels.ts` 只存关卡配置，不引用 Three.js：网格尺寸、光源方向与 `sourceEnergy`、镜面初始方向、`splitters`、带 `required` 的多目标、真实阻挡格、`solution`、`parMoves` 与所属 `district`。修改布局必须同时更新测试与视觉占位。
- `game/optics.ts` 是纯函数，不能访问 DOM、声音、存档或场景对象；`game/score.ts` 同样只由关卡配置与光路结果计算星级和能量利用率。
- 存档键为 `light-up-the-city-v2`（含 `best` 个人最佳）。v1 存档不迁移：关卡结构已变化，旧进度无对应语义。
- `scene/` 负责将规则映射成画面，不自行决定通关；命中目标以光路结果为准。
- `ui/` 只发出用户意图和渲染状态，不复制光路算法。
- `main.ts` 是流程协调者，负责串起状态、场景、UI、声音与本地存档。

## 添加或修改关卡

1. 在 `levels.ts` 中设置网格边界、光源方向与能量、镜子初始方向、分光器、各目标所需能量和真实阻挡格；同一 `district` 的两关共用一个街区中心，背景建筑按两关占用格的并集避让。
2. 在 `tests/optics.test.ts` 增加初始状态未通关、指定解法通关、重置恢复初始状态的测试；穷举求解器会校验每关至少一个解且 `parMoves` 等于最少操作次数。
3. 设计能量预算时先手算最优路径的剩余能量，再留 1–2 点余量给次优解；若希望评分有意义，至少提供两条可行路线（参考第 5 关）。
4. 运行逻辑测试，再用浏览器逐面镜子操作，确认错误路径的终点、分支颜色与目标「需/收」芯片和场景一致。
5. 检查每关点亮区域不会覆盖其他街区，终局仍能看到所有已完成区域。

## 视觉修改

先读 `docs/DESIGN.md`。共享材质与建筑细节放入 `scene/cityGeometry.ts`，关卡专属对象放入 `CityScene.ts`。避免在动画循环里创建材质、向量或音频节点。若引入新的资源，必须可本地打包并说明许可；核心游戏不能依赖远程资源。
