# 开发指南

## 分支与提交

- `main` 保持可构建、可玩；多人功能开发使用 `feat/<简短主题>`，修复使用 `fix/<简短主题>`。
- 提交前同步主干，提交信息使用 `feat:`、`fix:`、`test:`、`docs:`、`style:` 或 `refactor:` 前缀。
- 一个提交只包含一个可说明的阶段；不要提交 `node_modules`、`dist`、本机配置、账号信息或临时浏览器数据。

## 模块边界

- `game/levels.ts` 只存关卡配置，不引用 Three.js：网格尺寸、光源位置/方向/是否可转、`reflection`（背灯目标数、预置器件含锁定、库存、可选放置区）、`parMoves` 与所属 `district`。修改布局必须同时更新测试与视觉占位。
- `game/reflection.ts` 是纯函数规则引擎，不能访问 DOM、声音、存档或场景对象；`game/optics.ts` 仅保留光路结果类型；`game/score.ts` 只由关卡配置与操作次数计算星级。
- 存档键为 `light-up-the-city-v3`（含 `best` 个人最佳）。关卡重排后旧进度不迁移（按数字 ID 会错映射），仅从 v2 保留静音偏好。
- `scene/` 负责将规则映射成画面，不自行决定通关；命中目标以光路结果为准。
- `ui/` 只发出用户意图和渲染状态，不复制光路算法。
- `main.ts` 是流程协调者，负责串起状态、场景、UI、声音与本地存档。

## 添加或修改关卡

1. 在 `levels.ts` 中设置网格边界、光源与 `reflection` 配置（器件、锁定、库存、放置区、背灯目标数）；同一 `district` 的关卡共用一个街区中心，背景建筑按占用格的并集避让。
2. 在 `tests/reflection.test.ts` 增加初始状态未通关与参考解获胜的测试；`parMoves` 不高于参考解操作数。移植关保留原作布局与官方解，来源记录在 `docs/PORTING.md`。
3. 新机制必须先出现在简单可观察的教学环境，再进入复杂关卡；教学关应包含真实操作与规则发现，而非照答案点击。
4. 通关条件面板只展示本关实际存在的条件，直接复用 `ReflectionTrace` 与库存数据，不为 UI 新建规则计算。
5. 运行逻辑测试，再用浏览器逐件器件操作，确认分支颜色、器件状态环与条件面板和场景一致。
6. 检查每关点亮区域不会覆盖其他街区，终局仍能看到所有已完成区域。

## 视觉修改

先读 `docs/DESIGN.md`。共享材质与建筑细节放入 `scene/cityGeometry.ts`，关卡专属对象放入 `CityScene.ts`。避免在动画循环里创建材质、向量或音频节点。若引入新的资源，必须可本地打包并说明许可；核心游戏不能依赖远程资源。
